## Part 2. Создание виртуальных машин

Пришло время заготовить основу для будущих узлов кластера. Создадим виртуальную машину.

### Задание 

1) Установи и инициализируй Vagrant в корне проекта. Напиши Vagrantfile для одной виртуальной машины. Перенеси исходный код веб-сервиса в рабочую директорию виртуальной машины. Помощь по vagrant ты найдешь в материалах.
- Для установки **Vagrant** используются команды:
    1. **sudo apt update** - эта команда обновляет все текущие установленные пакеты.
    2. **sudo apt install vagrant virtualbox -y** - это команда для установки самого **Vagrant**
- Для проверки, что инструмент установился проверяем его версию **vagrant --version**:
```Vagrant 2.2.19```

- Далее нужно инициализировать в корне моего проекта (DO7) командой **vagrant init** - создан файл Vagrantfile, но он пока пустой.

- Создаем **Vagrantfile** для одной виртуальной машины:

![vagrantfile](./Screenshots/Part_2_Vagrantfile.png)

- В этом файле есть строка отвечающая за перенос исходного кода веб-сервиса в рабочую директорию виртуальной машины:
```config.vm.synced_folder "./services", "/services"```
- Эта команда копирует содержимое директории ***"./services"*** основной ВМ и переносит её в созданную при помощи **Vagrantfile** **"/services"**
- Для запуска ВМ нужно ввести простую команду ***vargant up*** и проверяем работо способность виртуальной машины ***vagrant status***

![vagrant up](./Screenshots/Part_2_vagrant_up.png)

![vagrant status](./Screenshots/Part_2_vagrant_status.png)

2) Зайди через консоль внутрь виртуальной машины и удостоверься, что исходный код встал, куда нужно. Останови и уничтожь виртуальную машину.

```Чтобы удачно подключиться к вм, нужно в настройках самой виртуальной машины зайти в Система -> Процессор -> поставить галочку напротив опции Enable Nested VT-x/AMD-V```
- При помощи команды **vagrant ssh**, которая была указана в **materials** подключаемся к виртуальной машине. Процесс подключения не быстрый, нужно немного подождать.
- Зайдя в ВМ проверяем, что директория с микросервисами перенеслась успешно **ls -la /services**
- Выходим из ВМ **exit**
- Командой **vagrant destroy -f** останавливаем и удаляем ВМ.

![vagrant ssh](./Screenshots/Part_2_vagrant_ssh.png)

![vagrant services and exit](./Screenshots/Part_2_vagrant_services_and_exit.png)

## Part 3. Создание простейшего Docker Swarm

Ну вот и пришло время создания твоего первого Docker Swarm!

### Задание

1) Модифицируй Vagrantfile для создания трех машин: manager01, worker01, worker02. Напиши shell-скрипты для установки Docker внутрь машин, инициализации и подключения к Docker Swarm. Помощь с Docker Swarm ты найдешь в материалах.
- Для начала в **Vagrantfile** создается 3 виртуальные машины, присваевается для каждой статический ip-адрес и запускаются написанные скрипты. 

![new vagrantfile](./Screenshots/Part_3_new_vagrantfile.png)

- Далее при помощи команды **scp** переносим все скрипты и модифицированный **Vagrantfile** на виртуальную машину.
- Командой **vagrant up** создаем написанные в файле 3 виртуальные машины одновременно для проверки, что машины соберутся и запустятся.
-  Заходим в **manager01** при помощи команды **vagrant ssh manager01** и проверяем, все узлы в кластере Docker Swarm **docker node ls**

![docker node ls](./Screenshots/Part_3_docker_node_ls.png)

2) Загрузи собранные образы на Docker Hub и модифицируй Docker Compose файл для подгрузки расположенных на Docker Hub образов.
- Нужно сначала залогиниться в **Docker Hub** из **manager01**
- Далее в **manager01** собираем образы микросервисов **docker build -t nieshays/session-service:latest .**, предворительно перейдя в папку с сервисами.
- Командой **docker push nieshays/session-service:latest** пушим в репозиторий на Docker Hub (nieshays - это мой ник, поэтому, чтобы не запутаться я использовал его.).
- И так далее с каждым сервисом.
- Зайдя в учетную запись **Docker Hub** проверяем, что все образы загружены успешно.

![docker hub](./Screenshots/Part_3_docker_hub.png)

3) Подними виртуальные машины и перенеси на менеджер Docker Compose файл. Запусти стек сервисов, используя написанный Docker Compose файл.
- Сперва запускаем все виртуальные машины **vagrant up**
- Пишем команду, которая перенесет файл **docker-compose.yml** в manager01 **vagrant upload docker-compose.yml /home/vagrant/ manager01** (Но у меня настроена синхронизация файлов между основной вм и manager01)
- Запускаем стек сервисов **docker stack deploy --with-registry-auth -c docker-compose.yml myapp** (Флаг **--with-registry-auth** передает учетные данные всех приватных образов на все виртуальные машины, чтобы доступ был у всех и ничего не потерялось)

![start stack](./Screenshots/Part_3_start_stack.png)

- Командой **docker service ps $(docker service ls -q)** проверяем, что у нас всё запустилось и без ошибок. А в случае ошибок **Docker Swarm** сам перезапустит сервисы.

![docker service ps](./Screenshots/Part_3_docker_service_ps.png)

4) Настрой прокси на базе nginx для доступа к gateway service и session service по оверлейной сети. Сами gateway service и session service сделай недоступными напрямую.
- Первым делом изменили конфигурацию файла **docker-compose.yml**. Убрали публичные порты у **session-service** и **gateway-service**, так как по заданию они не должны быть доступны напрямую

![deleted ports](./Screenshots/Part_3_deleted_ports.png)

- Затем добавляем в этот файл **nginx proxy**

![nginx proxy](./Screenshots/Part_3_added_nginx_in_file.png)

- Создается простой файл конфигурации **nginx**, который начинает слушать все входящие запросы на портах **8081 и 8087**, а затем перенаправляет их к реальным сервисам, то есть к **session-service** и **gateway-service**

![file nginx](./Screenshots/Part_3_nginx.conf.png)

- Так же важно указать в **docker-compose.yml** оверлейную сеть, чтобы через конфигурационный файл **nginx.conf** можно было получить доступ к сервисам, публичные порты которых мы убрали ранее, так как напрямую они теперь недоступны

![network overlay](./Screenshots/Part_3_overlay.png)

- Создаем **туннель** для портов через все уровни виртуальных машин, чтобы локальный хост **(в моем случает Windows 11)** получил доступ к **manager01**

![ports for ws11](./Screenshots/Part_3_ports_for_ws11.png)

- Оверлейная сеть нужна для трёх основных вещей:
    1. Изоляция и безопасность - сервисы недоступны снаружи, работают только через nginx
    2. Связь между разными машинами - cервисы на разных виртуальных машинах общаются как будто они в одной сети
    3. Простое общение по имени - не нужно запоминать ip-адреса. Docker автоматически находит сервисы по имени.

- Вывод команды **docker service ps $(docker service ls -q)** означающий, что все сервисы (в том числе и nginx) работают.

![services running](./Screenshots/Part_3_services_running.png)

- А если нужно вывести все сервисы, в том числе и неудачно запущенные, тогда подойдет команда **docker service ps $(docker service ls -q)**
